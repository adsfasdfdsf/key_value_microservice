
# **Key Value Service**

–  распределенное хранилище key-value пар
---



## **1. Описание функциональности**

Storage node выполняет следующие задачи:

- Ожидает запросов по адресам `GET /api/v1/value/{key}` `POST /api/v1/addValue`.
- Обрабатывает сообщения с определённой структурой.
- Логирует все основные этапы работы для дальнейшей отладки и анализа.

---

## **2. Архитектура**

Сервис состоит из следующих основных компонентов:

- **Nginx**: Роутит запросы на мастер или реплики в зависимости от типа сообщения.
- **Replica**: Может отвечать на *GetValue* сообщения.
- **Master**: Может отвечать на *AddValue* чтобы добавить новую пару и сообщает об этом репликам и на *GetValue* если реплики не доступны.

---

## **3. Взаимодействие и структура сообщений**

### **Endpoints**

Добавить пару:

`POST /api/v1/addValue`
и body в формате

```json
{
  "key": "string",
  "value": "string"
}
```
Ожидаемый ответ: 
* В случае успеха http.StatusCodeOK 
* В случае ошибки иной StatusCode

Получить значение:

`GET /api/v1/value/{key}`

Ожидаемый ответ: 

```json
{
  "key": "string",
  "value": "string"
}
```
А также
* В случае успеха http.StatusCodeOK 
* В случае ошибки иной StatusCode

### **Grpc сообщения которыми обмениваются master-replica**

Формат Proto:

```proto
message AppendValueRequest {
    string key = 1;
    string value = 2;
}
```
Ожидаемый ответ:
```proto
message AppendValueResponse {
    bool success = 1;
}
```
